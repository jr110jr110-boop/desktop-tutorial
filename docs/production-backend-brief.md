# Production / shop floor (MES) and maintenance, release P1 — backend brief

Ground rules, CI loop and design principles: as in /home/claude/innco/docs/quality-backend-brief.md ("Ground rules", "CI loop", "Addendum") — binding. Prefix `Mf`, routes `api/v1/production`, sequence kinds 481–500, constants `ProductionRoles`. Migration `ProductionMes`. Depends on finance F2 (`FnEmployee`, payroll hourly cost) and on project control (CPM, activities) and quality (ITP, QcRecord, NCR).

## Existing code to reuse (do not duplicate)
- Legacy planning chain: Contract → WorkOrder → AssemblyEntity → Bom → ProcessEntity (one process per BOM line, `ProcessType` Buy/Service/Assembly/FinalAssembly/Construction), generated from Equipment templates. Project control already makes one `PcActivity` per ProcessEntity and runs CPM, mirroring dates back.
- Execution/traceability chain: `OperationTemplate` (routing step per item or item group) → `PartOperation` (per serial/lot; start/finish/QC), `SerialUnit`, `InventoryLot`, `AssemblyLink`, StageConversion documents, MaterialRequest (planning + manufacturing approval), SubcontractIssue/Return, ServiceAcceptance, Subcontract purchase orders.
- `Machine` (only Id/Title/IsActive), `PcCalendar` (+ exceptions), company holidays.
**Decision ★:** do not add a third routing model. `OperationTemplate` becomes the single routing master (extended). The legacy `ProcessEntity` of type Construction/Service/Assembly/FinalAssembly is the planning container: a production order is created per such process (or per BOM line marked make) and its operations are copied from the item's routing; `PartOperation` rows are created automatically from production-order operations for each serial/lot, so the existing traceability screens keep working.

## 1. Master data
- `MfWorkCenter` (code, title, kind {Machine, ManualStation, Welding, AssemblyBay, TestStand, Painting, Outside}, calendar (PcCalendar id), shifts per day, hours per shift, efficiency % (default 100), utilisation % (default 85 ★), number of parallel resources, hourly machine rate (rial, set by finance), cost centre, queue days default, isActive). `MfMachineInfo` 1:1 side table of `Machine` (work centre, asset id (finance F2 `FnAsset`, nullable), maker, model, serial, capabilities text, status {Available, Down, UnderMaintenance, Retired}).
- `OperationTemplate` extension (side table `MfOperationStandard` 1:1): work centre, setup hours, run hours per unit, move/queue days, outside operation flag + default supplier + lead days, work instruction document (quality document control id), drawing reference rule, required qualification kind/process (welding: WPS required), inspection requirement {None, Self, Qc, ItpPoint}, ITP test type link, first-article required.
- Routing revision: `MfRoutingRevision` per item/group (revision, status Draft/Approved, approved by PRODUCTIONMANAGER + ENGINEERING (two people)); only approved routings can be used for new production orders.

## 2. Production orders (دستور تولید داخلی)
- `MfProductionOrder` (number PO-MF-, work order, contract, legacy process id (nullable), BOM line id, item, quantity, unit, serials/lots planned, routing revision, status {Draft, Released, InProgress, Completed, Closed, Cancelled}, priority (computed: CPM total float ascending, then need date), need date (= late finish of the linked PcActivity, else work order date), planned start/finish (scheduler), actual start/finish).
- **System drafts:** when a work order's WBS is generated or a make process becomes ReadyToGo, the system drafts production orders and their operations. Humans release.
- **Release gate** (SHOPSUPERVISOR or PRODUCTIONMANAGER) checks, all computed: routing approved; drawings required by the routing are MDR lines Approved (internal) for this work order; ITP approved when the work order has one; material availability (components from the BOM: on-hand in company warehouses not reserved + open PO lines with delivery ≤ planned start) — shortage list allowed only with PRODUCTIONMANAGER override and reason; work-centre exists and is not Retired.
- On release: the system drafts the MaterialRequest (kit) for components (existing approvals apply) and creates `PartOperation` rows per serial/lot.
- `MfOperation` (order, sequence, template, work centre, setup/run hours planned, planned start/finish, status {Waiting, Ready, InProgress, Paused, Done, QcHold, Rejected, Skipped}, good/scrap/rework quantities, outside PO line id, QC record/NCR links). Rules: an operation is Ready when the previous operation is Done (or Skipped with reason by SHOPSUPERVISOR) and, if the previous operation requires QC/ITP point, its QC is accepted (H points: ITP release required); first operation Ready when the kit is issued (issue documents cover the kit or override). Rework creates a rework operation copy linked to the NCR.
- Outside operations: on Ready the system drafts a Subcontract purchase request line (existing procurement) and the SubcontractIssue document draft; the operation completes on SubcontractReturn + incoming QC acceptance / ServiceAcceptance.
- Completion: last operation Done → ProductionReceipt document drafted (existing inventory) into WIP/finished goods per item stage; serial status update stays in inventory.

## 3. Time booking and shop-floor terminal
- `MfTimeBooking` (operation, employee (FnEmployee) — derived from the logged-in user's employee link, machine (nullable), kind {Setup, Run, Rework, Waiting, Cleaning}, start, end (null while running), hours computed, good qty, scrap qty with reason code, rework qty, note, source {Terminal, Supervisor}). One running booking per employee at a time (starting a new one stops the previous). Bookings by a supervisor for someone else need a reason. Edits after the day closes only by SHOPSUPERVISOR with reason (audit).
- Terminal endpoints (tablet UI): scan job card / serial label → my operations; start/pause/finish; report quantity and scrap; request QC (creates the QC request for QC users' inbox); report machine down (creates a maintenance request).
- Waiting/downtime reason codes table `MfReasonCode` (kind {Scrap, Downtime, Waiting}).
- **Daily cost posting** (hosted service at 02:00 ★): for each closed booking: labour cost = hours × employee hourly cost rate (from finance F2: the last approved payroll month's total employer cost of the employee / paid hours; until a payroll exists, the work-centre standard labour rate) + machine cost = hours × work-centre machine rate → `CostEntry` Kind Labour / Overhead per work order and WBS node (feeds project control AC and EV) and the accounting event "labour absorbed" (Dr WIP 10520 / Cr absorbed labour and overhead 70102/70103 ★ — finance reconciles absorbed vs actual monthly).
- The attendance-to-booking check: hours booked per employee per day vs attendance hours (office automation) → difference list for the supervisor.

## 4. Scheduling and capacity
- Finite-capacity scheduler (deterministic, re-runnable, endpoint + nightly ★): operations of Released/InProgress orders, sorted by order priority; each operation scheduled forward from max(previous operation finish + move days, today, kit ready date) on its work centre's calendar with available hours = shifts × hours × parallel resources × efficiency × utilisation − maintenance downtime; outside operations use lead days; results written to planned start/finish; order finish compared with need date → late flag and days late.
- Results feed project control: the linked `PcActivity` gets a forecast finish (not the baseline) — reuse the existing forecast field.
- Load report: hours per work centre per week (12 weeks) vs capacity; overload list. Dispatch list per work centre (Ready and next operations in priority order) — printable job cards (front prints; backend JSON).

## 5. Maintenance (CMMS basic)
- `MfMaintenancePlan` (machine, task, interval {Days, RunningHours ★ from bookings}, last done, next due, checklist text, estimated hours). Hosted service drafts `MfMaintenanceOrder` when due (−7 days ★). `MfMaintenanceRequest` (breakdown; from terminal or user), order (planned/breakdown, status {Open, InProgress, Done, Cancelled}, downtime start/end, spare parts issued (existing Issue document with cost centre maintenance), labour bookings, cause, action). Machine status Down while a breakdown order is open; scheduler excludes downtime.
- KPIs (read only): MTBF, MTTR per machine; availability; OEE per work centre (availability × performance (standard hours / booked run hours) × quality (good / (good + scrap))).

## 6. Dashboards and alerts
- Production dashboard: orders late vs need date, operations in QC hold > 2 days, overload weeks, kit shortages, machines down, maintenance overdue, scrap rate this month, OEE.
- CEO dashboard additions + alerts: late production orders, machines down, overload > 110 % next 4 weeks.
