H1 Change control bypass: CreateBaselineAsync (S/ProjectControl/PcBaselineService.cs:126-139) issues baseline N+1 without a change request (spec: required for any number above 0); activities/dependencies/WBS stay editable after an approved baseline (PcScheduleService.cs:653-724, 818-865, 161-198, AutoWeights 312-324, GenerateWbsAsync 380-531 re-weights/adds work orders); DecideAsync (:488-517) rebuilds the baseline from ALL current values (absorbs unapproved edits); live weights drive the progress-percent payment trigger (PcCommercialService.cs:159-161). Fix: lock the schedule while a baseline is current (edits only through change-request scenario items add/modify/remove), require an approved CR for any baseline after the first.
H2 Terms change without amendment: SaveTermsAsync (PcProjectService.cs:106-140; PMO, PLANNING, COMMERCIAL, PROJECTMANAGER) overwrites value, penalty rate, cap, grace days, delivery date, management reserve, ClientReportShowsIndices at any time, no approval/audit; PlannedDeliveryDate per work order (:314). Fix: freeze commercial fields once the contract review is accepted; change only via CEO-approved amendment or variation order; audit.
H3 Variation orders self-approved; amendments ignored: VariationActionAsync (PcCommercialService.cs:580-608) one user create/submit/approve with free-text client reference; approved VOs raise contract value (:62-73) and push penalty dates (:455); CEO-approved amendments (PcProjectService.cs:760-820) count in neither. Fix: VO needs a decided CR or CEO-approved amendment plus a second approver; one instrument used consistently in value and penalty calculations.
H4 Data-date discipline: EV always from today's progress (PcProgressService.cs:86-89, 147-148; only PV/AC respect asOf :505-512); TakeSnapshotAsync accepts any past data date, defaults to last Wednesday (:677-678); snapshots immutable; smoke back-dates a snapshot 14 days and books future cost entries (smoke :1160, :1149-1150); actual start can be future (PcScheduleService.cs:748). Fix: progress as of the data date from dated events; back-dating only with PMO approval + reason; reject future actual/cost dates.
H5 Penalties double-counted; partial deliveries count as delivered: ComputePenaltiesAsync (PcCommercialService.cs:459-476) adds a per-work-order item and a whole-contract item, each with its own cap; actual date = latest delivered shipment. Fix: company chooses the basis (★ default: per contract); one overall cap; delivery counts only when full quantity delivered.
H6 Purchasing authority/quote rule bypass: required quotes and medium/major approvals come only from the requester's estimate (ProcurementService.cs:262, 311-318, 342, 484; estimates optional → 0); SaveOrderAsync takes ProviderId/InquiryId/prices/quantities from the request unchecked (:815-845); approval only checks some inquiry id (:869). Fix: re-check quotes/approval level against the selected quote's value; lock order supplier/lines to the selected quote (changes routed through approval); validate inquiry status and request lines.
