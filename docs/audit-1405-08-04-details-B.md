# Audit B findings (quality, production/MES, after-sales, inventory) — verbatim from the independent reviewer (paths: B/ = /home/claude/backend/src/, F/ = /home/claude/front/src/, services under B/Services/NasbNiro/<Module>/)

## High
D1 — Production labour cost reveals one person's hourly pay. Production/MfCostService.cs:306-317 writes an exact CostEntry (Labour) per work order / WBS / work centre / day, and :321-330 a WIP line per work order. MfCostMask at :134-141 masks only the production DTOs. ProjectControl/PcProgressService.cs:609-619 (controller ProjectControlControllers.cs:231-233) returns raw cost rows to PMO, PLANNING, PROJECTMANAGER, QC, QA, ENGINEERING, WAREHOUSE; the same roles see every booking with employee name and hours (MfShopFloorService.cs:577-600); finance readers see the event lines. Fix: reuse the after-sales approach (SvCommon.cs:397-403): protected groups (fewer than 3 payroll-rated employees) posted only as a monthly aggregate without the work-order split; mask protected amounts in the project-control cost list and finance events.
D2 — The monthly after-sales labour total is not itself checked for privacy. AfterSales/SvLabourService.cs:93-119 and SvCommon.cs:451-486 never test whether the whole month is protected; SvOrderService.cs:108-119 exposes each engineer's hours and LabourAggregatePeriod to order readers. Fix: if the month as a whole is protected, carry it to the next month; hide LabourAggregatePeriod and per-employee hours from non-payroll roles.
D3 — No maker-checker on NCRs; the inspector who raised a failed-test NCR can cancel it alone. Inventory/InventoryQualityService.cs:564-590 excludes only the other approvers, not the creator; closing (:701-733) and cancelling (:707-715) open to any PMO or QC user (InventoryControllers.cs:200-215). Fix: exclude creator/editors from the QC signature and from closing; cancelling needs a QC manager who is not the creator; no cancelling of NCRs drafted from failed tests unless a re-test exists.
D4 — Rework disposition moves nonconforming stock into a usable warehouse with no re-inspection (InventoryQualityService.cs:637-642; transfer confirm marks the NCR Executed, InventoryDocumentService.cs:1186-1196; closing :718-724 needs only typed text). Fix: rework destination = quarantine/QC-hold with an inspection on arrival; closing requires an accepted re-inspection record linked to the NCR.
D5 — Shop-floor NCRs are "executed" with no record (InventoryQualityService.cs:616-624). Fix: scrap must produce a scrap document or serial status change; rework must be linked to a finished rework operation with an accepted inspection.
D6 — A production order can never finish after a reject followed by concession or scrap (Production/MfFlow.cs:61-77; MfProductionService.cs:593-600 skips only Waiting/Ready; :770-775 rework only for Rework disposition). Fix: "accept by concession" action requiring an approved NCR concession; for scrap reduce the quantity and draft a replacement order.
D7 — Every operation expects the full order quantity even after earlier scrap (MfShopFloorService.cs:371-376, :418-420). Fix: expected quantity = previous operation's good quantity.
D8 — Rework starts before the review board approved the disposition (MfProductionService.cs:724-728; :772-775). Fix: create rework only when the NCR is Approved with Rework disposition.
D9 — The vendor can bypass client/third-party inspection points in the ITP (Quality/ItpService.cs:534-540 "not applicable" by QC/QA/PMO with a note while :588-591 forbids waiving a hold point; NoticeDays editable after client approval :360-371; notification date can be any past date :516-522 → "waived by notice" :168-175). Fix: N/A on client/third-party hold or witness points needs a client reference and an ITP revision; lock notice days once approved; notification date = server time or an outgoing-letter reference.
D10 — Customer-delivery release gate is weak (Quality/ReleaseService.cs:51-56 only checks a released note exists per work order; :259-265 NCRs by work order only; Inventory/InventoryDocumentService.cs:805-814 skips the release check whenever a service order is attached). Fix: release notes with item/serial lines; re-check open NCRs at delivery; limit service-order deliveries to spare parts.
D11 — Warehouse staff can switch off QC gates on an item (Inventory/InventoryMasterService.cs:313-314; save endpoint allows WAREHOUSE/WHSUPERVISOR, InventoryControllers.cs:54-56). Fix: only QC/QA may edit quality fields, audited, second approval.
D12 — Welder qualification and WPS not enforced at the point of welding (ProductionEntities.cs:84-87 stores required qualification for the job card only; starting an operation MfShopFloorService.cs:235-304 checks nothing). Fix: starting a welding operation requires an approved WPS and a valid qualification of the booking employee (link qualified person ↔ employee); draft the weld log from the booking.
D13 — CAPA owners outside the quality roles are locked out and CAPAs never escalated (QualityCommon.cs:21 readers; QualityControllers.cs:276-278; CapaService.cs:64-69, :283-286; no quality nightly job). Fix: owners/action owners read their own CAPA; inbox task per action owner; nightly escalation to QA and CEO.
